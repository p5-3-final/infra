# /sdd-implement: 태스크 단위 구현

입력: $ARGUMENTS (Claude Code에서는 인자로 치환된다. 다른 도구에서는 사용자 요청에서 파악한다)

1. `specs/<SPEC 폴더>/plan.md`와 `tasks.md`를 읽는다. 태스크 번호가 주어지면 그 태스크를, 없으면 첫 번째 미완료 태스크를 고른다. 선행 태스크가 끝났는지 확인한다.
2. 그 태스크가 담당하는 요구사항(`R-n`)의 EARS 문장을 spec에서 다시 읽는다.
3. **Red**: 요구사항을 검증하는 테스트를 작성하고, 실행해서 기능이 없어서 실패하는 것을 확인한다. 컴파일 오류나 설정 오류로 인한 실패는 먼저 고친다. 테스트 이름에는 `[SPEC-NNN R-n]`을 포함한다.
4. **Green**: 테스트를 통과시키는 데 필요한 최소한의 코드만 작성한다.
5. **Refactor**: 테스트가 통과하는 상태를 유지하면서 중복과 이름을 정리한다. 태스크 범위 밖의 리팩터링은 하지 않는다. 주석은 루트 AGENTS.md의 "주석 규칙"을 따른다(왜를 쓰고, 공개 인터페이스에는 문서 주석).
6. **검증**: 이 레포 AGENTS.md의 lint, 타입 검사, 테스트 명령을 실행한다. 실패하면 원인을 고친다. 테스트를 비활성화하거나 검사를 무력화해서 통과시키지 않는다.
7. **기록**: `tasks.md`에서 해당 태스크를 `[x]`로 바꾼다. 구현이 plan과 달라졌다면 plan도 갱신한다. spec이나 계약과 충돌하면 멈추고 사용자에게 알린다.
8. **보고**: 변경 파일, Red 실패 출력과 Green 통과 출력 요약, 제안 커밋 메시지를 알린다. 커밋 메시지 형식은 `<type>(<scope>): <한국어 설명>` + `Refs: SPEC-NNN`이다.

한 번에 태스크 하나만 처리한다. 커밋은 사용자가 요청할 때만 한다.
